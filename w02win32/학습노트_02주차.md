# [02주차] 「학번」 「이름」

Win32 API로 창을 띄우고, 클릭한 자리에 노란 원(파란 테두리)을 그리는 프로그램을
단계별로 개발하며 기능들을 배웠다.

(캡처 1: 원을 여러 개 찍은 실행 화면)

## 단계별로 배운 것

**1. 사각형 그리기** — 먼저 `WM_PAINT`에서 사각형 하나를 그렸다.
`Rectangle(hdc, 10, 10, 100, 100)`처럼 시작점(왼쪽 위)과 끝점(오른쪽 아래) 좌표로
도형을 지정한다는 것, 화면 좌표는 왼쪽 위가 `(0,0)`이고 아래로 갈수록 y가 커진다는 것을 배웠다.
그리려면 먼저 `HDC`(그릴 대상)를 `BeginPaint`로 받고 `EndPaint`로 돌려줘야 한다는 것도 알았다.

**2. 마우스 클릭 이벤트** — `WM_LBUTTONDOWN`을 추가해 클릭하면 `MessageBox`가 뜨게 했다.
`WndProc`의 `switch`에 `case`를 추가하면 그 이벤트를 처리할 수 있다는 구조를 배웠다.
오른쪽 버튼은 `L`을 `R`로, 버튼을 뗄 때는 `DOWN`을 `UP`으로 바꾸면 된다는 것도 배웠다.
(`WM_RBUTTONDOWN`, `WM_LBUTTONUP`)

**3. 클릭하면 사각형 그리기** — 알림창 대신 도형을 그려 봤다.
`WM_PAINT` 밖에서 그리려면 `GetDC`로 HDC를 따로 받아오고
`ReleaseDC`로 돌려줘야 한다는 것을 배웠다. (`BeginPaint`는 `WM_PAINT` 안에서만 쓴다)

**4. 클릭한 위치에 그리기** — 항상 같은 자리에 그려지던 걸 클릭 지점으로 바꿨다.
마우스 좌표가 `lParam`에 들어오고, 32비트 안에 x와 y가 16비트씩 담겨 있어서
`LOWORD(lParam)`, `HIWORD(lParam)`으로 잘라 쓴다는 것을 배웠다.

**5. 채우기 색 바꾸기** — `CreateSolidBrush`로 노란 브러시를 만들어 적용했다.
`SelectObject`로 HDC에 끼우면 원래 끼워져 있던 것이 반환값으로 나오고,
다 쓰면 그걸 다시 끼운 다음에 `DeleteObject`로 지워야 한다는 순서를 배웠다.
끼워져 있는 상태에서는 삭제가 안 되기 때문이다.

**6. 원으로 바꾸고 테두리 색 지정** — `Rectangle`을 `Ellipse`로 바꾸니
인자는 그대로인데 원이 그려졌다. 테두리는 브러시가 아니라 `CreatePen`으로 만든
펜(`HPEN`)이 담당한다는 것, 펜도 브러시와 똑같은 순서로 되돌리고 지워야 한다는 것을 배웠다.

여기서 문제를 하나 발견했다. 창을 다른 창으로 가렸다 열면 그려둔 원이 지워졌다.
Windows는 가려진 부분을 복원해 주지 않고 `WM_PAINT`를 보내 다시 그리게 하는데,
좌표를 저장해두지 않아서 다시 그릴 수가 없었기 때문이다.

**7. 좌표를 변수에 저장** — 그래서 클릭할 때는 좌표만 저장하고,
그리기는 전부 `WM_PAINT`로 옮겼다. `WM_PAINT`는 몇 번 다시 불려도 같은 그림을 만들어야 한다는 걸 배웠다.

```c
static int x = -100, y = 100;   // 좌표 저장용 전역 변수

case WM_LBUTTONDOWN:
    x = LOWORD(lParam);   // 그리지 않고 좌표만 저장
    y = HIWORD(lParam);
    break;

case WM_PAINT:
    Ellipse(hdc, x - 30, y - 30, x + 30, y + 30);   // 저장된 좌표로 그림
    break;
```

그런데 이번엔 클릭해도 화면이 안 바뀌었다. 창을 가렸다 열면 그때만 그려졌다.

**8. `InvalidateRect`로 해결** — 좌표가 바뀐 걸 Windows는 모르니
`WM_PAINT`를 보낼 이유가 없었던 것이다. 한 줄을 추가해 해결했다.

```c
case WM_LBUTTONDOWN:
    x = LOWORD(lParam);
    y = HIWORD(lParam);
    InvalidateRect(hWnd, NULL, TRUE);   // ★ 다시 그려달라고 요청
    break;
```

`InvalidateRect`는 "창 내용이 낡았다"고 표시해두는 함수고, 그러면 Windows가 알아서
`WM_PAINT`를 보내준다. `WM_PAINT`를 직접 호출하는 게 아니라 보내달라고 요청하는
구조라는 걸 배웠다. 세 번째 인자는 다시 그리기 전에 배경을 지울지 정하는 값이다.

**9. 모델 분리** — 원을 여러 개 그리려고 좌표를 배열에 저장하면서, 저장하는
부분을 `model.h` / `model.cpp`로 따로 뺐다. `POINT`는 x, y를 묶은 구조체라 `p.x`, `p.y`로 쓴다는 것,
`model.cpp`의 배열은 `static`이라 밖에서 직접 못 건드리고 함수를 거쳐야 한다는 것(캡슐화),
그래서 저장 방식은 `model`만, 그리는 모양은 `W02Win32.cpp`만 고치면 된다는 것을 배웠다.

```c
// model.h - 저장하는 쪽의 사용 설명서
#define MODEL_MAX_POINTS	20

int   GetNumPoints();       // 저장된 개수
POINT GetPoint(int);        // i번째 점
void  AddPoint(POINT);      // 점 추가
void  DeleteLastPoint();    // 마지막 점 삭제
```

```c
// W02Win32.cpp - 그리는 쪽. 저장된 점을 전부 다시 그린다
case WM_LBUTTONDOWN:
    {
        POINT p;
        p.x = LOWORD(lParam);
        p.y = HIWORD(lParam);
        AddPoint(p);                        // 모델에 좌표만 넘김
        InvalidateRect(hWnd, NULL, TRUE);
    }
    break;

case WM_PAINT:
    {
        // ... 브러시와 펜은 반복문 밖에서 한 번만 끼운다
        int n = GetNumPoints();
        for (int i = 0; i < n; i++) {
            POINT p = GetPoint(i);
            Ellipse(hdc, p.x - 30, p.y - 30, p.x + 30, p.y + 30);
        }
    }
    break;
```

## 이번 주 핵심

그리기는 무조건 `WM_PAINT`에서 하고, 다른 곳에서는 데이터만 바꾼 뒤
`InvalidateRect`로 다시 그려달라고 요청한다.
6~8단계에서 반대되는 두 증상을 직접 겪으면서 이 구조를 이해하게 됐다.

## 바꿔 본 것

### 1. 오른쪽 버튼으로 Undo

`model.cpp`에 `DeleteLastPoint()`가 이미 있는데 아무 데서도 안 부르길래 연결해 봤다.
2단계에서 배운 대로 `L`을 `R`로 바꾼 메시지를 쓰면 됐다.

```c
case WM_RBUTTONDOWN:
    {
        DeleteLastPoint();                  // 마지막 점 삭제
        InvalidateRect(hWnd, NULL, TRUE);   // 다시 그려달라고 요청
    }
    break;
```

**결과:** 오른쪽 클릭할 때마다 원이 하나씩 사라졌다.
`case` 하나 추가한 게 전부고 그리는 코드는 하나도 안 건드렸다.

(캡처 2: 오른쪽 클릭으로 원을 하나 지운 화면)

### 2. 저장 개수 늘리기

원을 3개 찍으면 더 이상 안 찍혀서 찾아보니 `model.h`에 상한이 있었다.

```c
#define MODEL_MAX_POINTS	20   // 원래 3
```

**결과:** 20개까지 찍혔다. `model.h`의 숫자 하나만 고쳤고 `W02Win32.cpp`는 안 건드렸다.
9단계에서 파일을 나눠 놓은 효과를 확인했다.

## 막혔던 것

- `error C2374: 'hdc': 재정의` — `WM_PAINT` 안에서 `BeginPaint`로 받아놓고 `GetDC`로 또 선언함
- `LNK1168: exe를 열 수 없습니다` — 이전에 실행한 앱이 안 꺼져 있어서. 창 닫으니 해결

## 더 알아볼 것

- `wParam`, `lParam`은 메시지마다 의미가 달라서 매번 찾아봐야 하는지
- 브러시·펜을 안 지우면 생긴다는 GDI 누수가 실제로 어떤 문제가 되는지
