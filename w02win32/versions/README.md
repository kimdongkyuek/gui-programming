# Win32 2주차 단계별 정리 (GA3018)

교수님 강의노트([Notion](https://nano5.notion.site/Win32-c3cdaf211d42822e9eb6814fd8a92bf3))의 진행 순서를
**9단계**로 나눠서, 각 단계마다 **그 자체로 빌드되는 완성 파일**을 만들어 둔 폴더입니다.

각 `.cpp` 파일 맨 위에는 "이 단계에서 하는 일 / 새로 나온 것 / 실행하면 어떻게 되는지"가
주석으로 적혀 있고, 새로 추가된 코드 줄마다 설명이 붙어 있습니다.
이 문서는 그 위에서 **전체 흐름과 개념**을 잡기 위한 것입니다.

---

## 0. 사용법

보고 싶은 버전을 `w02win32\w02win32\w02win32.cpp` 자리에 덮어쓰고 `Ctrl+F5` 로 실행하면 됩니다.
v9만 파일이 3개라 폴더로 되어 있습니다.

> **주의:** 이 `versions` 폴더는 프로젝트(`.vcxproj`)에 포함시키면 안 됩니다.
> 모든 파일에 `wWinMain` 이 하나씩 들어 있어서, 같이 컴파일하면
> "이미 정의되어 있습니다"(LNK2005) 링크 에러가 납니다.

## 1. 먼저 큰 그림: Win32는 "메시지"로 돌아간다

C 콘솔 프로그램은 `main`이 위에서 아래로 흐르다가 끝나면 종료됩니다.
Windows 프로그램은 **전혀 다른 구조**입니다. 이거 하나만 이해하면 나머지는 따라옵니다.

```
사용자가 마우스 클릭
        ↓
Windows가 "WM_LBUTTONDOWN 메시지"를 만들어 우리 프로그램 줄에 세움
        ↓
wWinMain 안의 while 루프(메시지 루프)가 그걸 하나 꺼냄   ← GetMessage
        ↓
꺼낸 메시지를 WndProc 함수에 배달                        ← DispatchMessage
        ↓
WndProc 의 switch 문에서 case WM_LBUTTONDOWN 실행
```

정리하면:

| 하는 일 | 누가 |
|---|---|
| 무슨 일이 생겼는지 알려 줌 | Windows |
| 그 소식을 꺼내서 배달 | 메시지 루프 (`wWinMain`의 `while`) |
| 소식에 따라 실제 동작 | **`WndProc`** ← 우리가 코드를 쓰는 곳 |

**그래서 이 수업에서 우리가 건드리는 곳은 거의 항상 `WndProc` 안의 `switch` 문입니다.**
`wWinMain`, `MyRegisterClass`, `InitInstance` 는 템플릿이 만들어 준 그대로 두고 거의 안 건드립니다.

`WndProc`의 매개변수 4개:

| 이름 | 뜻 |
|---|---|
| `hWnd` | 어느 창인지 (창의 번호표) |
| `message` | 무슨 일인지 (`WM_PAINT`, `WM_LBUTTONDOWN` …) |
| `wParam` | 부가 정보 1 |
| `lParam` | 부가 정보 2 — **마우스 메시지에서는 클릭 좌표가 들어옴** |

내가 `case`로 안 적은 메시지는 맨 아래 `default:`의 `DefWindowProc`이 처리합니다.
창 이동, 크기 조절, 닫기 버튼 같은 기본 동작이 전부 거기서 나옵니다. 지우면 안 됩니다.

## 3. 꼭 알아야 할 개념 3개

### (1) HDC = 그림을 그릴 "도화지"

Win32에서는 그냥 `Rectangle(10,10,100,100)` 하고 그릴 수 없습니다.
**어디에 그릴지**를 먼저 받아 와야 하고, 그게 `HDC`(Device Context 핸들)입니다.

도화지를 빌리는 방법이 **두 가지**이고, 쓰는 자리가 정해져 있습니다.

| | 어디서 쓰나 | 빌리기 | 돌려주기 |
|---|---|---|---|
| `BeginPaint` / `EndPaint` | **`WM_PAINT` 안에서만** | `BeginPaint(hWnd, &ps)` | `EndPaint(hWnd, &ps)` |
| `GetDC` / `ReleaseDC` | **`WM_PAINT` 밖에서** | `GetDC(hWnd)` | `ReleaseDC(hWnd, hdc)` |

둘 다 **반드시 짝을 맞춰야** 합니다. 돌려주지 않으면 자원이 새서
오래 실행하면 그림이 아예 안 그려집니다.

### (2) GDI 객체는 "만들기 → 끼우기 → 되돌리기 → 지우기" 4단계

색을 바꾸려면 브러시(안쪽)나 펜(테두리)을 만들어 도화지에 끼워야 합니다.
강의노트에 "**사용한 후에는 반드시 돌려 놓아야 함**"이라고 굵게 적힌 부분입니다.

```c
HBRUSH yellow, oldBrush;
yellow   = CreateSolidBrush(RGB(255, 255, 0));   // 1) 만들고
oldBrush = (HBRUSH)SelectObject(hdc, yellow);    // 2) 끼우고 ← 원래 것을 꼭 보관!

Rectangle(hdc, ...);                             // 3) 그리고

SelectObject(hdc, oldBrush);                     // 4) 원래 것으로 되돌린 다음
DeleteObject(yellow);                            //    내가 만든 걸 지운다
```

**왜 되돌린 다음에 지우나?** 도화지에 끼워져 있는 상태의 객체는 삭제가 안 되기 때문입니다.
순서를 지키지 않으면 `DeleteObject`가 조용히 실패하고 GDI 누수가 생깁니다.

펜도 똑같습니다. 여러 개 끼웠으면 **끼운 순서의 반대로** 되돌리는 습관을 들이세요.

| | 역할 | 만드는 함수 |
|---|---|---|
| `HBRUSH` | 도형 **안쪽** 채우기 | `CreateSolidBrush(RGB(r,g,b))` |
| `HPEN` | 도형 **테두리** 선 | `CreatePen(PS_SOLID, 굵기, RGB(r,g,b))` |

### (3) 좌표는 `lParam` 안에 두 개가 겹쳐 들어 있다

```c
int x = LOWORD(lParam);   // 아래 16비트 → x
int y = HIWORD(lParam);   // 위  16비트 → y
```

`lParam`은 32비트인데, 마우스 메시지에서는 그 안에 x와 y를 16비트씩 나눠 담아서 보냅니다.
그래서 반씩 잘라 꺼내는 것입니다.

> `lParam`의 첫 글자는 **소문자 L**입니다 (`Long`의 L). 숫자 1도, 대문자 I도 아닙니다.
> 좌표 기준점은 **창의 클라이언트 영역** 좌상단이라, 제목 표시줄 바로 아래가 `(0, 0)`입니다.

## 4. 이 주차의 핵심: v6 → v7 → v8

가장 헷갈리는 부분이라 따로 떼서 설명합니다. **증상이 정반대로 두 번 바뀝니다.**

### v6의 증상 — 클릭하면 그려지는데, 창을 가렸다 열면 사라짐

`WM_LBUTTONDOWN`에서 `GetDC`로 직접 그렸습니다. 그리는 순간에는 잘 보입니다.
그런데 다른 창이 우리 창을 덮었다가 비키면 그 부분이 지워져 있습니다.

**왜?** Windows는 가려졌던 부분을 **복원해 주지 않습니다.**
대신 우리에게 `WM_PAINT`를 보내서 "네가 다시 그려라"라고 시킵니다.
그런데 우리 `WM_PAINT`에는 원을 그리는 코드가 없습니다.
클릭할 때 화면에 칠하기만 했지, **어디에 그렸는지 아무 기록도 남기지 않았기 때문**입니다.

> 화이트보드에 그림을 그렸는데, 누가 지웠을 때 다시 그릴 수 있게
> **좌표를 수첩에 적어 두지 않은 것**과 같습니다.

### v7의 해결 시도 — 좌표를 저장하고 `WM_PAINT`에서 그리자

```c
static int x = -100, y = 100;   // 수첩 (전역 변수)
```

- `WM_LBUTTONDOWN` : 좌표를 **저장만** 함 (그리기 코드는 전부 주석 처리)
- `WM_PAINT` : 저장된 `x`, `y`를 보고 원을 그림

발상은 정확히 맞습니다. `WM_PAINT`는 몇 번을 다시 불려도 항상 같은 그림을 만들어 냅니다.

> 처음 값이 `-100`인 이유는, 프로그램을 켠 직후에는 화면 **밖**에 그려서
> 아무것도 안 보이게 하려는 것입니다.

### v7의 증상 — 클릭해도 아무 일이 없음 (v6과 정반대!)

그런데 창을 화면 밖으로 내렸다 올리면 **그제서야** 원이 나타납니다.

**왜?** 좌표는 잘 저장됐습니다. 문제는 **아무도 "다시 그려라"라고 말해 주지 않았다**는 것입니다.
`x`, `y`가 바뀐 건 우리만 아는 사실이고, Windows 입장에서는 화면에 아무 변화가 없으니
`WM_PAINT`를 보낼 이유가 없습니다.
창을 가렸다 열면 그때는 Windows가 알아서 `WM_PAINT`를 보내니까 그제야 그려지는 것입니다.

### v8의 해결 — `InvalidateRect` 한 줄

```c
InvalidateRect(hWnd, NULL, TRUE);
```

- `valid` = 적절한 / `in-` = 반대 / `-ate` = 동사로 만듦
- → **"이 창의 내용은 이제 유효하지 않다"**고 표시하는 함수

표시해 두면 Windows가 잠시 후 알아서 `WM_PAINT`를 보내 줍니다.
**`WndProc`을 내가 직접 부르는 게 아니라, 보내 달라고 부탁하는 것**이 핵심입니다.

| 인자 | 뜻 |
|---|---|
| `hWnd` | 어느 창을 |
| `NULL` | 창 전체를 (일부만 원하면 `RECT` 주소) |
| `TRUE` | 다시 그리기 전에 **배경을 지울지** |

세 번째 인자를 `FALSE`로 바꿔서 실행해 보면 차이가 바로 보입니다.
`TRUE`면 이전 원이 지워지고 새 원 하나만, `FALSE`면 이전 그림 위에 덧그려집니다.

### 세 줄 요약

> **그리기는 무조건 `WM_PAINT`에서.**
> **다른 곳에서는 데이터만 바꾸고 `InvalidateRect`로 부탁.**
> 이게 Windows 그래픽 프로그래밍의 기본 골격입니다.

## 5. v9 — 왜 파일을 나누나 (모델 분리)

v8까지는 원이 **딱 하나**뿐입니다. 좌표를 한 쌍만 저장하니까요.
여러 개 그리려면 배열이 필요하고, 그러면 `W02Win32.cpp`가 점점 복잡해집니다.

그래서 역할을 나눕니다.

| 파일 | 역할 | 아는 것 |
|---|---|---|
| `model.h` / `model.cpp` | 점들을 **저장·관리** (데이터) | 배열, 개수 — 화면은 모름 |
| `W02Win32.cpp` | **화면에 그리기** + 마우스 받기 | HDC, 펜, 브러시 — 저장 방식은 모름 |

```c
// model.h — "무엇을 할 수 있는지"만 적는 사용 설명서
int  GetNumPoints();        // 저장된 개수
POINT GetPoint(int);        // i번째 점
void AddPoint(POINT);       // 추가
void DeleteLastPoint();     // 마지막 하나 삭제 (Undo)
```

`model.cpp`의 배열은 `static`이라 **밖에서 직접 못 건드립니다.**
반드시 위 함수들을 거쳐야 하고, `AddPoint` 안에 범위 검사가 있으니
실수로 배열 밖을 쓰는 사고가 안 납니다. 이걸 **캡슐화**라고 합니다.

이렇게 나누면 고칠 곳이 명확해집니다.

- "원 말고 별을 그리자" → `W02Win32.cpp`만
- "3개 말고 100개 저장하자" → `model.h`의 `MODEL_MAX_POINTS`만

`WM_PAINT`는 저장된 점을 전부 도는 반복문으로 바뀝니다.
브러시와 펜은 **반복문 밖에서 한 번만** 끼우고 안에서 재사용하는 게 포인트입니다.

```c
int n = GetNumPoints();
for (int i = 0; i < n; i++) {
    POINT p = GetPoint(i);
    Ellipse(hdc, p.x - 30, p.y - 30, p.x + 30, p.y + 30);
}
```

`POINT`는 `x`, `y`를 한 덩어리로 담는 Windows 기본 구조체입니다 (`p.x`, `p.y`).

## 6. 도전 과제 힌트

강의노트 마지막의 "조금 바꿔 볼 것"입니다.

### 오른쪽 버튼으로 Undo

`model.cpp`에 `DeleteLastPoint()`가 이미 있는데 아직 아무도 안 부릅니다. 이걸 쓰면 됩니다.
`WndProc`에 `case`를 하나 추가하세요.

```c
case WM_RBUTTONDOWN:
    {
        DeleteLastPoint();                  // 마지막 점 삭제
        InvalidateRect(hWnd, NULL, TRUE);   // 다시 그려 달라고 요청
    }
    break;
```

### 드래그하면 계속 추가

`WM_MOUSEMOVE`를 처리하되, 버튼을 누른 상태일 때만 추가해야 합니다.
`wParam`에 버튼 상태가 들어옵니다.

```c
case WM_MOUSEMOVE:
    if (wParam & MK_LBUTTON) {   // 왼쪽 버튼을 누른 채 움직이는 중
        // AddPoint + InvalidateRect
    }
    break;
```

`MODEL_MAX_POINTS`가 3이라 금방 꽉 찹니다. 숫자를 늘려서 해 보세요.

### 그 밖에

- 클릭할 때마다 색이 바뀌게 (색 배열을 만들고 인덱스를 돌리기)
- 원 크기를 랜덤하게 (`model`에 반지름도 같이 저장)
- 가운데 버튼(`WM_MBUTTONDOWN`)으로 전체 지우기

| 증상 | 원인 / 해결 |
|---|---|

| `error C2065: 'x': 선언되지 않은 식별자` | v7/v8에서 전역 `static int x, y`를 안 만들었거나, `//int x, y;` 주석을 잘못 풀었을 때 |

| `LNK1168: w02win32.exe을(를) 열 수 없습니다` | **앱이 아직 실행 중**입니다. 창을 닫고 다시 빌드 (강의노트에도 나오는 내용) |
| `warning C4819: 코드 페이지(949)…` | 파일이 BOM 없는 UTF-8로 저장됨. VS에서 **파일 → 다른 이름으로 저장 → 인코딩 지정 → "유니코드(서명 있는 UTF-8)"** |

| 창 가리면 그림이 지워짐 | `WM_PAINT` 밖에서 그리고 있음 (= v6 상태) |

> 참고: `F5`는 디버깅 실행, `Ctrl+F5`는 디버깅 없이 실행입니다.
> 디버깅을 끌 때는 `Shift+F5`.
