# [03주차] 「학번」 「이름」 — MFC Doc/View

> 제출 전 이 줄은 지우세요. 「」 채우고, (캡처 N) 자리에 스크린샷 붙이면 됩니다.

## 만든 것

MFC **앱 마법사**로 프로젝트를 만들고, 클릭한 자리에 원을 그리는 프로그램.
지난주에는 `CWinApp` + `CFrameWnd` 두 개를 직접 상속해서 만들었는데,
이번엔 마법사가 **클래스 4개를 만들어 주고** 나는 거기에 코드만 채워 넣었다.

(캡처 1: 클릭해서 원이 그려진 실행 화면)

## 단계별로 배운 것

**1. 프로젝트 생성 — 옵션이 곧 구조다**

C++ → **MFC 앱** → 애플리케이션 종류 **단일 문서**, 프로젝트 스타일 **MFC standard**.
문서 템플릿 속성에서 확장명을 `cir`로 지정했다.
이건 `*.cir` 파일을 더블 클릭하면 이 프로그램이 열리도록 **OS에 등록**한다는 뜻이다.
문서를 파일로 저장하고 여는 기능이 처음부터 들어있는 구조라는 걸 알았다.

View의 **기반 클래스를 고를 수 있다**는 게 인상적이었다.
그림을 그리려면 `CView`, 에디터를 만들려면 `CEditView`를 고르면 되고,
`CEditView`로 만들면 편집·복사·저장이 **코드 한 줄 없이** 다 동작한다고 한다.

**2. 마법사가 만들어 준 클래스 4개**

| 클래스 | 상속 | 역할 |
|---|---|---|
| `CG26W03MFCApp` | `CWinApp` | 프로그램 전반. 앱당 **반드시 하나** |
| `CMainFrame` | `CFrameWnd` | 창 바깥 틀 (최소화·최대화·닫기). **프로젝트 이름이 안 붙는다** |
| `CG26W03MFCDoc` | `CDocument` | 데이터 관리 (비즈니스 로직) |
| `CG26W03MFCView` | `CView` | 클라이언트 영역 (흰 부분, 그림 그리는 곳) |

이름 규칙이 `C` + 프로젝트이름 + `App`/`Doc`/`View`인데 `CMainFrame`만 예외다.
`CAboutDlg`도 있는데 이건 정보 대화상자용이라 4개에 안 들어간다.

지난주에 배운 **상속 + 재정의**를 마법사가 대신 해 준 것이다. 예를 들어 App 클래스는:

```cpp
class CG26W03MFCApp : public CWinApp
{
public:
    virtual BOOL InitInstance();   // 시작할 때
    virtual int  ExitInstance();   // 끝날 때
};
```

`virtual`이 붙어 있어야 자식이 재정의할 수 있다는 것도 다시 확인했다.
(C++는 `virtual` 필요 / Java는 전부 가능 / C#은 `virtual` + `override` 둘 다 필요)

**3. 클래스 마법사로 메시지 처리 추가**

View에서 오른쪽 버튼 → **클래스 마법사**(`Ctrl+Shift+X`) → 메시지 탭 →
`WM_LBUTTONDOWN` → 처리기 추가 → 코드 편집.

중요한 건 **코드가 세 군데에 나뉘어 들어간다**는 점이다.

| 위치 | 들어간 것 |
|---|---|
| `View.h` | `afx_msg void OnLButtonDown(UINT nFlags, CPoint point);` |
| `View.cpp` 위쪽 메시지 맵 | `ON_WM_LBUTTONDOWN()` |
| `View.cpp` 맨 밑 | `OnLButtonDown()` 함수 본체 |

**지우고 싶으면 세 군데를 다 지워야 한다.** 하나만 지우면 빌드 에러가 난다.
지난주엔 이 세 줄을 손으로 썼는데 마법사가 대신 써 주는 것뿐, 구조는 똑같았다.

**4. 일단 그려보기 → 문제 발견**

```cpp
void CG26W03MFCView::OnLButtonDown(UINT nFlags, CPoint point)
{
    CClientDC dc(this);
    dc.Ellipse(point.x - 30, point.y - 30, point.x + 30, point.y + 30);

    CView::OnLButtonDown(nFlags, point);
}
```

실행하면 클릭한 자리에 원이 그려지는데, **창을 가렸다 열면 지워진다.**
지난주 Win32에서 겪은 것과 **똑같은 문제**다.
`OnDraw`가 다시 그려야 하는데 좌표를 아무 데도 저장하지 않았기 때문이다.

(캡처 2: 창을 가렸다 열었더니 원이 지워진 화면)

**5. Doc/View 구조로 해결**

MFC는 **Doc/View**라는 구조를 쓴다. MVC를 변형한 것이다.

| 일반 용어 | MFC | 이번 코드에서 |
|---|---|---|
| Model | **Document** | 클릭 좌표 `Point` 보관 |
| View + Controller | **View** | 클릭 받기 + 원 그리기 |

**Document — 데이터만 갖는다** (`~Doc.h`)

```cpp
protected:
    CPoint Point = CPoint(-100, -100);
public:
    CPoint GetPoint() { return Point; }
    void SetPoint(CPoint p) { Point = p; }
```

`Point`를 `protected`로 막고 Getter/Setter로만 접근하게 했다.
처음 값이 `(-100, -100)`인 건 시작하자마자 화면 밖에 그려서 안 보이게 하려는 것이다.
(지난주 Win32에서 `static int x = -100`과 같은 수법)

`~Doc.cpp`의 `OnNewDocument()`에도 초기화를 넣었다.
**단일 문서(SDI)는 새 문서를 만들 때 기존 객체를 재사용**하기 때문에,
"새 파일"을 눌러도 이전 좌표가 남지 않게 여기서 다시 초기화해 줘야 한다.

```cpp
    Point = CPoint(-100, -100);
```

**View — 저장하고 요청만 한다** (`~View.cpp`)

```cpp
void CG26W03MFCView::OnLButtonDown(UINT nFlags, CPoint point)
{
    //CClientDC dc(this);
    //dc.Ellipse(point.x - 30, point.y - 30, point.x + 30, point.y + 30);

    GetDocument()->SetPoint(point);   // Doc에 저장
    Invalidate();                     // 다시 그려달라고 요청

    CView::OnLButtonDown(nFlags, point);
}
```

**View — 그릴 때 Doc에서 꺼내 온다**

```cpp
void CG26W03MFCView::OnDraw(CDC* pDC)   // 원래 /*pDC*/ 로 주석 처리되어 있음
{
    CG26W03MFCDoc* pDoc = GetDocument();
    ASSERT_VALID(pDoc);
    if (!pDoc)
        return;

    CPoint p = pDoc->GetPoint();
    pDC->Ellipse(p.x - 30, p.y - 30, p.x + 30, p.y + 30);
}
```

`OnDraw`의 매개변수가 `CDC* /*pDC*/`로 **주석 처리되어 있어서 그냥 쓰면 에러**가 난다.
주석을 풀어 `CDC* pDC`로 바꿔야 한다. (안 쓰는 매개변수 경고를 없애려고 그렇게 해 둔 것)

(캡처 3: 창을 가렸다 열어도 원이 남아 있는 화면)

## 왜 OnPaint가 아니고 OnDraw인가

제일 궁금했던 부분이다.

- `WM_PAINT`를 처리하는 함수는 원래 `OnPaint()`가 맞다.
- 그런데 MFC는 `OnPaint()` 안에서 `OnDraw()`를 불러 준다.
- **화면 출력과 프린터 출력을 같은 코드로 처리**하기 위해서다.
  화면이면 `pDC`가 화면 DC, 인쇄면 프린터 DC가 들어온다.
- `WM_DRAW`라는 메시지는 **없다.** `OnDraw`는 메시지 처리 함수가 아니라
  MFC가 부르는 가상 함수다.

Android의 View도 `onDraw()`라는 걸 보니 프레임워크마다 비슷하게 설계하는 것 같다.

## 흐름 정리

```
왼쪽 클릭
   │
   ▼
View::OnLButtonDown(point)
   │  GetDocument()->SetPoint(point)   ← Doc(데이터)에 저장
   │  Invalidate()                      ← "화면 낡았음" 표시
   ▼
MFC가 WM_PAINT 발생시킴 → OnPaint() → View::OnDraw(pDC)
   │  pDoc->GetPoint()                  ← Doc에서 꺼내기
   ▼
pDC->Ellipse(...)                       ← 그리기
```

**View는 데이터를 갖지 않고, Doc은 그리지 않는다.**
이렇게 나누니까 화면이 몇 번 다시 그려져도 원이 사라지지 않는다.

## 명령어·함수 정리

| 코드 | 의미 |
|---|---|
| `CWinApp` | 앱 전체. `InitInstance()` / `ExitInstance()` 재정의 |
| `CFrameWnd` | 창 바깥 틀. 최소화·최대화·닫기 담당 |
| `CDocument` | 데이터 담당. MVC의 **Model** |
| `CView` | 클라이언트 영역. MVC의 **View + Controller** |
| `GetDocument()` | View에서 자기 Document를 얻는 함수. **마법사가 이미 만들어 놨다** |
| `ASSERT_VALID(pDoc)` | 디버그 빌드에서 포인터가 유효한지 검사 |
| `OnNewDocument()` | 새 문서를 만들 때 호출. SDI는 객체를 재사용하므로 초기화 자리 |
| `OnDraw(CDC* pDC)` | 화면·프린터 공통 그리기 함수. **`OnPaint`가 대신 불러 준다** |
| `Invalidate()` | "다시 그려라" 요청 → `OnDraw`까지 이어짐 |
| `CClientDC dc(this)` | `WM_PAINT` **밖에서** 그릴 때 쓰는 DC (Win32의 `GetDC`) |
| `CPaintDC` | `OnPaint` **안에서** 쓰는 DC (Win32의 `BeginPaint`/`EndPaint`) |
| `CPoint` | x, y를 담는 클래스. `p.x`, `p.y` |
| `afx_msg` | 메시지 처리 함수 표시 (재정의용 `virtual`과 구분하려고) |
| `ON_WM_LBUTTONDOWN()` | 왼쪽 클릭 메시지를 `OnLButtonDown`에 연결하는 매크로 |
| `CView::OnLButtonDown(nFlags, point)` | 부모 것도 호출. 기본 동작을 막지 않으려고 남겨 둔다 |

## 지난주(간단한 MFC)와 비교

| 지난주 | 이번주 |
|---|---|
| `CWinApp`, `CFrameWnd` 2개를 직접 상속 | 마법사가 4개 생성 (App/MainFrame/Doc/View) |
| 메시지 맵을 손으로 작성 | **클래스 마법사**가 3군데 자동 삽입 |
| 좌표를 창 클래스의 멤버 변수에 저장 | **Document**에 저장 (Getter/Setter) |
| `OnPaint()`에서 그림 | `OnDraw(CDC* pDC)`에서 그림 |
| `CPaintDC dc(this)` | 인자로 받은 `pDC` 사용 |
| 파일 저장 기능 없음 | `Serialize()` 자리가 이미 있음 (`*.cir`) |

지난주 코드는 창 하나짜리라 데이터를 창이 들고 있어도 됐는데,
데이터가 많아지고 저장까지 하려면 Doc으로 빼는 게 맞다는 게 이해됐다.

## 막혔던 것

**`OnDraw`의 `pDC`가 없다는 에러**
`void CG26W03MFCView::OnDraw(CDC* /*pDC*/)`처럼 매개변수 이름이 주석이라
`pDC->Ellipse(...)`를 쓰면 "정의되지 않은 식별자"가 뜬다. 주석만 풀면 된다.

**GitHub 저장소를 못 만듦**
Git 메뉴에 **Git 리포지토리 만들기**가 아예 안 떴다.
프로젝트 폴더를 **이미 git 저장소인 폴더 안에** 만들어서, VS가 "이미 저장소 안"이라고
판단한 것이 원인이었다. 저장소 밖으로 옮기니 메뉴가 나왔다.

## 더 알아볼 것

- `Serialize()`로 `*.cir` 파일 저장/열기 구현해 보기
- View 기반 클래스를 `CEditView`로 바꾸면 정말 편집기가 되는지
- Doc 하나에 View를 여러 개 붙이면 어떻게 되는지 (분할 창)

## 도전 과제

- [ ] 원을 **여러 개** 저장하고 출력하기 (`CPoint` 배열 또는 `CArray`)
- [ ] 마우스 **오른쪽 버튼**으로 undo (`WM_RBUTTONDOWN` → 마지막 좌표 제거 → `Invalidate()`)
